# Security policy

## Reporting a security concern

Please do not publish passwords, access tokens, private keys, personal records, payroll data or private user files in a public issue.

Where GitHub Private vulnerability reporting or Security Advisories is enabled for this repository, use that private channel. If it is not available, use the contact method linked from the repository owner's GitHub profile and provide only the minimum information needed to reproduce the concern.

Do not include real user data in proof-of-concept material. Redact domains, identifiers, tokens and personal information where possible.

## Scope

This repository is a static personal website and project directory. Security reports may cover the site, build/deployment workflows, configuration publishing workflow, service worker and repository-controlled scripts. Issues in linked applications should be reported to their relevant repositories.

## Response expectations

Reports will be reviewed as capacity permits. A report is not a guarantee of a particular response time or bounty. Please allow the maintainer an opportunity to investigate before public disclosure.

## Safe testing

Only test systems and data you own or are authorised to use. Do not attempt denial-of-service, credential theft, destructive actions or access to other users' data.
